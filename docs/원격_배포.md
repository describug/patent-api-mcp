# 원격 서버로 배포하기 (Cloud Run)

patent-api는 원래 **내 컴퓨터에서** 도는 도구다(Claude Code·데스크톱 확장, stdio). 이 문서는 같은 코드를
**인터넷 주소가 있는 서버**로 띄워 Gemini Enterprise·ChatGPT·개인 Gemini 앱에서 쓰는 방법이다.

- 로컬(stdio) 사용과 `.mcpb` 확장은 **바뀌지 않는다.** 원격 모드는 `PATENT_API_TRANSPORT=http`일 때만 켜진다.
- 원격 모드는 **반드시 로그인(OAuth)** 을 요구한다. 허용 목록이 비어 있으면 서버가 아예 시작하지 않는다.
- 아래 명령은 구글 클라우드(Cloud Run) 기준이다. 화면·메뉴 이름은 2026년 10월 기준이라 바뀌었을 수 있다.

---

## 1. 먼저 정할 것: 세 가지 운영 방식

| | ① 회사 서버 1개 | ② 나만 쓰는 서버 | ③ 지인 각자 서버 |
|---|---|---|---|
| 누가 쓰나 | 회사 직원 전체 | 나 혼자 | 지인 한 명 한 명 |
| 누가 배포하나 | **회사 IT** | 나 | 지인 각자 |
| 구글 클라우드 프로젝트 | 회사 프로젝트 | 내 프로젝트 | 각자 프로젝트 |
| KIPRIS·EPO 키 | **회사 명의로 발급한 키** | 내 키 | 각자 키 |
| 허용 목록 | `PATENT_API_ALLOWED_DOMAINS=회사도메인` | `PATENT_API_ALLOWED_EMAILS=내메일` | `PATENT_API_ALLOWED_EMAILS=본인메일` |
| 쓰는 앱 | Gemini Enterprise(관리자가 1번 등록) | ChatGPT·개인 Gemini·Claude | ChatGPT 등 |
| 구글 로그인 화면 대상 | 내부(Internal) | 외부(External) + 테스트 사용자 | 외부(External) + 테스트 사용자 |

**회사용은 ①을 권장한다.** 회사 프로젝트에 회사 명의 키로 IT가 배포해야, 사내 승인·비용·키 관리·퇴사자 처리가
회사 절차 안에 들어간다. **개인 키를 회사 서버에 넣지 않는다**(KIPRIS 월 1,000회 한도를 전 직원이 나눠 쓰게 되고,
키 주인이 퇴사하면 서버가 멈춘다). 회사 시스템 연동은 사내 승인을 먼저 받는다.

> ### ⚠️ '인증 없음'으로 등록하지 말 것
> Gemini Enterprise·ChatGPT는 MCP 서버를 **인증 없음(No authentication)** 으로도 등록할 수 있다. 그렇게 만든 서버는
> 주소만 알면 **누구나** 회사 키로 조회할 수 있다 — 한도가 바닥나고, 키 약관 위반이 되고, 남의 검색어가 회사 이름으로
> 나간다. 이 서버는 허용 목록 없이 시작하지 않고 토큰 없는 요청을 `401`로 거절하므로, 앱에서도 반드시 **OAuth**를
> 고른다. 코드를 고쳐 인증을 끄지 않는다.

## 2. 인증 설계 (왜 이렇게 만들었나)

앱마다 로그인 방식이 다르다.

| 앱 | 등록 방식 |
|---|---|
| Gemini Enterprise 커스텀 MCP 커넥터 | 관리자가 **인증 URL·토큰 URL·클라이언트 ID**(·PKCE)를 손으로 넣는다. 자동 발견(디스커버리)·동적 등록(DCR) 없음 |
| ChatGPT 개발자 모드 커넥터, 개인 Gemini 앱 Custom apps | **서버 주소만** 넣으면 `/.well-known/oauth-protected-resource` 등을 읽고 **동적 등록(DCR)** 으로 스스로 등록 |

사람 확인은 **구글 계정**으로 한다(회사가 구글 워크스페이스를 쓴다). 선택지는 셋이었다.

| 선택지 | 내용 | 장점 | 단점 |
|---|---|---|---|
| A. 구글을 직접 인가 서버로 | 앱이 구글 로그인 URL로 바로 가고, 서버는 구글 토큰만 확인 | 서버 코드 최소 | **구글은 DCR을 지원하지 않아** ChatGPT·개인 Gemini가 붙지 못한다. 구글 접근 토큰은 확인할 때마다 구글에 물어야 한다 |
| **B. 얇은 인가 서버 (채택)** | 이 서버가 `/authorize`·`/token`·`/register`를 열고, 로그인 자체는 구글에 넘긴 뒤 허용 목록을 통과하면 자기 토큰을 준다 | 두 방식(수동 입력·DCR)을 한 서버로 모두 받는다. 외부 서비스 추가 없음 | 인가 서버 코드를 우리가 관리한다(아래처럼 범위를 최소로 했다) |
| C. 외부 IdP (Auth0, Okta, Keycloak 등) | 인가·DCR을 외부 서비스에 맡기고 서버는 토큰 확인만 | 표준 기능이 풍부(감사 로그, 강제 로그아웃 등) | 계정·요금·설정이 하나 더 늘고, 회사 승인 대상이 늘어난다 |

**B를 가장 단순하게 구현했다.**

- 저장소(DB) 없음: 클라이언트 등록·로그인 중 상태·인가 코드·토큰을 모두 `PATENT_API_AUTH_SECRET`으로 **서명한 문자열**로 만든다.
  그래서 Cloud Run이 재시작하거나 인스턴스가 여러 개여도 연결이 끊기지 않는다.
- 허용 목록은 **로그인할 때와 매 요청마다** 다시 확인한다. 목록에서 빼고 재배포하면 그 사람의 기존 토큰도 다음 요청부터 거부된다.
- 도메인 허용(`PATENT_API_ALLOWED_DOMAINS`)은 그 도메인의 **구글 워크스페이스 계정**만 인정한다(구글이 주는 `hd` 값으로 확인).
  같은 주소로 만든 개인 구글 계정은 통과하지 못한다. 개인 Gmail 등은 `PATENT_API_ALLOWED_EMAILS`에 한 명씩 넣는다.
- 동적 등록은 **허용된 리디렉션 호스트**(ChatGPT·Gemini·Claude·내 컴퓨터)만 받는다. 아무 사이트나 등록해 로그인 코드를 빼 가는 것을 막는다.
- PKCE(S256)를 항상 요구한다.
- 토큰 수명: 접근 1시간, 갱신 30일. 개별 토큰 폐기 기능은 없다 → 허용 목록에서 빼거나, 서명 키를 바꿔 전원을 끊는다.
- 범위(scope)는 `patent` 하나다.

## 4. 배포 단계

### 4-1. 프로젝트 고르기·기능 켜기

```bash
gcloud auth login
gcloud config set project <프로젝트ID>
gcloud services enable run.googleapis.com secretmanager.googleapis.com cloudbuild.googleapis.com artifactregistry.googleapis.com
```

이후 명령에서 쓸 값을 셸에 담아 둔다(터미널을 새로 열면 다시 실행).

```bash
PROJECT_ID=$(gcloud config get-value project)
PROJECT_NUMBER=$(gcloud projects describe "$PROJECT_ID" --format='value(projectNumber)')
REGION=asia-northeast3                      # 서울
SERVICE=patent-api
URL="https://${SERVICE}-${PROJECT_NUMBER}.${REGION}.run.app"
SA="patent-api-run@${PROJECT_ID}.iam.gserviceaccount.com"
echo "$URL"
```

Cloud Run 주소는 `https://서비스-프로젝트번호.지역.run.app` 모양으로 **미리 정해진다.** 이 주소(`$URL`)를 아래 구글 로그인 설정과
`PATENT_API_PUBLIC_URL`에 쓴다. (사내 정책으로 다른 주소·자체 도메인을 쓰면 그 주소로 바꾼다.)

### 4-2. 서버 전용 서비스 계정

서버가 비밀값을 읽을 때 쓰는 계정이다. 기본 계정 대신 권한이 최소인 전용 계정을 만든다.

```bash
gcloud iam service-accounts create patent-api-run --display-name="patent-api Cloud Run"
```

### 4-3. 구글 로그인 설정 (OAuth 클라이언트)

사용자가 "구글로 로그인"할 때 쓰는 설정이다. 콘솔 화면에서 한다.

1. [Google Auth Platform](https://console.cloud.google.com/auth/overview)을 연다(같은 프로젝트인지 위쪽에서 확인).
2. **브랜딩**: 앱 이름(예: `patent-api`), 지원 이메일을 넣는다.
3. **대상(Audience)**:
   - ① 회사 서버: **내부(Internal)** — 회사 워크스페이스 계정만 로그인 화면을 통과한다(서버의 허용 목록과 이중 확인).
   - ②③ 개인 서버: **외부(External)** 로 두고 **테스트 사용자**에 쓸 사람의 구글 계정을 넣는다(100명까지, 앱 검토 불필요).
4. **데이터 액세스**: 범위는 기본(`openid`, `email`)이면 된다. 민감한 범위를 추가하지 않는다.
5. **클라이언트 → 클라이언트 만들기**: 유형 **웹 애플리케이션**, 승인된 리디렉션 URI에 아래를 넣는다.

   ```
   https://patent-api-<프로젝트번호>.asia-northeast3.run.app/oauth/google/callback
   ```
   (`echo "$URL/oauth/google/callback"`으로 나온 값. 끝까지 정확히 같아야 한다.)
6. 만들어진 **클라이언트 ID**를 적어 두고, **클라이언트 보안 비밀**은 다음 단계에서 바로 Secret Manager에 넣는다(파일·메신저에 붙여 두지 않는다).

```bash
GOOGLE_CLIENT_ID=<클라이언트 ID>.apps.googleusercontent.com
```

### 4-4. 비밀값을 Secret Manager에

키는 이미지·코드·환경변수 평문에 두지 않고 Secret Manager에 둔다. 입력한 값이 화면과 셸 기록에 남지 않게 `read -rs`로 받는다
(붙여 넣고 Enter. 화면에는 아무것도 안 보이는 게 정상).

```bash
make_secret() {   # 사용법: make_secret 비밀이름  → 값을 붙여 넣고 Enter
  local v; read -rs v; printf '%s' "$v" | gcloud secrets create "$1" --data-file=- --replication-policy=automatic; unset v
  gcloud secrets add-iam-policy-binding "$1" --member="serviceAccount:$SA" --role=roles/secretmanager.secretAccessor >/dev/null
}

make_secret kipris-service-key            # KIPRIS Plus 인증키
make_secret epo-ops-consumer-key          # EPO OPS Consumer Key
make_secret epo-ops-consumer-secret       # EPO OPS Consumer Secret
make_secret google-oauth-client-secret    # 4-3의 클라이언트 보안 비밀
```

토큰 서명 키는 사람이 정하지 않고 무작위로 만든다.

```bash
openssl rand -base64 48 | tr -d '\n' | gcloud secrets create patent-api-auth-secret --data-file=- --replication-policy=automatic
gcloud secrets add-iam-policy-binding patent-api-auth-secret --member="serviceAccount:$SA" --role=roles/secretmanager.secretAccessor
```

### 4-5. 배포

저장소 폴더에서 실행한다. `Dockerfile`로 이미지를 만들어(Cloud Build) Cloud Run에 올린다. 몇 분 걸린다.

```bash
gcloud run deploy "$SERVICE" \
  --source . \
  --region "$REGION" \
  --service-account "$SA" \
  --allow-unauthenticated \
  --max-instances 1 \
  --memory 512Mi \
  --set-secrets "KIPRIS_SERVICE_KEY=kipris-service-key:latest,EPO_OPS_CONSUMER_KEY=epo-ops-consumer-key:latest,EPO_OPS_CONSUMER_SECRET=epo-ops-consumer-secret:latest,PATENT_API_AUTH_SECRET=patent-api-auth-secret:latest,GOOGLE_OAUTH_CLIENT_SECRET=google-oauth-client-secret:latest" \
  --set-env-vars "PATENT_API_PUBLIC_URL=$URL,GOOGLE_OAUTH_CLIENT_ID=$GOOGLE_CLIENT_ID,PATENT_API_ALLOWED_DOMAINS=<회사도메인>,PATENT_API_OAUTH_CLIENT_ID=gemini-enterprise,KIPRIS_MONTHLY_LIMIT=1000"
```

- 허용 목록은 방식에 맞게 바꾼다: ① `PATENT_API_ALLOWED_DOMAINS=example.com` / ②③ `PATENT_API_ALLOWED_EMAILS=me@gmail.com`.
  **여러 개는 `;`로 구분**한다(`a@gmail.com;b@gmail.com`). 쉼표는 gcloud가 다른 뜻으로 쓴다.
- `PATENT_API_OAUTH_CLIENT_ID`는 Gemini Enterprise처럼 OAuth 값을 손으로 넣는 앱을 쓸 때만 필요하다(값은 아무 이름이나, 예: `gemini-enterprise`).
- `--allow-unauthenticated`는 Cloud Run 앞문(구글 IAM 확인)을 여는 설정이다. ChatGPT·Gemini는 구글 IAM 토큰을 보낼 수 없어서 필요하다.
  **문을 지키는 것은 이 서버의 OAuth**이고, 로그인하지 않은 요청은 `401`로 거절된다. 회사 조직 정책이 공개 서비스를 막으면 IT가 예외를 정한다.
- `--max-instances 1`: 호출 수 집계를 한 곳에서 하도록(아래 6장).
- 배포가 끝나면 나오는 `Service URL`이 `$URL`과 같은지 확인한다. 다르면 그 주소로 `PATENT_API_PUBLIC_URL`과 4-3의 리디렉션 URI를 고친다.

### 4-6. 확인

```bash
curl -s "$URL/healthz"                                         # {"ok":true}
curl -s -o /dev/null -w '%{http_code}\n' -X POST "$URL/mcp"    # 401 (로그인 없이는 거절 — 정상)
curl -s "$URL/.well-known/oauth-protected-resource/mcp"        # resource, authorization_servers
curl -s "$URL/.well-known/oauth-authorization-server"          # authorize·token·register 주소
```

서버 로그는 `gcloud run services logs read "$SERVICE" --region "$REGION" --limit 50`.
허용 목록이 비었거나 설정이 빠지면 시작하지 않고, 빠진 항목을 한국어로 로그에 적는다.

## 5. 앱에 등록하기

서버 주소(MCP 엔드포인트)는 `$URL/mcp`다. 전송 방식은 **Streamable HTTP**다(SSE는 쓰지 않는다).

### 5-1. Gemini Enterprise (관리자가 한 번, 팀 전체)

관리 콘솔에서 커스텀 MCP 서버(커넥터)를 추가하고, 인증 방식을 **OAuth**로 골라 아래를 넣는다.

| 칸 | 값 |
|---|---|
| 서버 URL | `https://patent-api-<번호>.asia-northeast3.run.app/mcp` |
| 인증 URL (Authorization URL) | `https://patent-api-<번호>.asia-northeast3.run.app/authorize` |
| 토큰 URL (Token URL) | `https://patent-api-<번호>.asia-northeast3.run.app/token` |
| 클라이언트 ID | 4-5에서 넣은 `PATENT_API_OAUTH_CLIENT_ID` 값(예: `gemini-enterprise`) |
| 클라이언트 보안 비밀 | 비워 둔다. 필수 칸이면 아무 값이나 넣는다(이 서버는 비밀 대신 **PKCE**로 확인한다) |
| PKCE | **켠다**(이 서버는 PKCE 없는 요청을 받지 않는다) |
| 범위(scope) | `patent` (비워 둬도 된다) |

- 관리 화면에 **리디렉션 URI**가 보이면 그 호스트가 허용 호스트(기본에 `vertexaisearch.cloud.google.com` 포함)에 있는지 확인한다.
  없으면 6-4처럼 추가한다.
- 직원은 처음 쓸 때 구글 로그인 창에서 **회사 계정**으로 로그인한다.

### 5-2. ChatGPT (각자)

1. ChatGPT **설정 → 앱과 커넥터(Apps & Connectors) → 고급 설정**에서 **개발자 모드**를 켠다
   (회사·팀 요금제는 관리자가 허용해야 보일 수 있다).
2. **만들기(Create)** → 이름 `patent-api`, MCP 서버 URL `$URL/mcp`, 인증 **OAuth**.
3. 저장하면 ChatGPT가 서버를 스스로 발견·등록하고 구글 로그인 창을 띄운다. 허용된 계정으로 로그인한다.

### 5-3. 개인 Gemini 앱 Custom apps

> **제약(2026-10 기준, 업체 안내서 종합):** 개인 Gemini 앱의 Custom apps는 **Gemini Ultra 구독, 미국, 영어 설정,
> Spark 환경**에서만 쓸 수 있다. 조건이 안 맞으면 메뉴가 보이지 않는다.

1. Custom apps에서 새 앱을 추가하고 서버 URL `$URL/mcp`를 넣는다.
2. ChatGPT처럼 디스커버리·동적 등록으로 스스로 등록하고 구글 로그인 창을 띄운다.
3. 등록이 "redirect URI" 오류로 실패하면 서버 로그에서 `동적 등록 거부: 허용되지 않은 리디렉션 호스트 [...]` 줄을 찾아
   그 호스트를 6-4처럼 추가한다(기본 목록에 `gemini.google.com`이 있지만 실제 주소가 다를 수 있다).

### 5-4. (참고) Claude에서 원격 서버로

```bash
claude mcp add --transport http patent-api-remote "$URL/mcp"
```

claude.ai 사용자 지정 커넥터에도 같은 주소를 넣으면 된다. 내 컴퓨터에서만 쓸 거면 원격 서버 없이 README의 로컬 설치가 더 간단하다.

## 6. 운영

### 6-1. 캐시와 KIPRIS 호출 수는 재시작하면 지워질 수 있다

원격 모드의 캐시·호출 기록은 기본으로 `/tmp/patent-api-mcp/cache.sqlite3`에 둔다. **Cloud Run의 디스크는 휘발성**(메모리 위의 임시 공간)이라
서버가 재시작되거나, 요청이 없어 꺼졌다가(0대로 축소) 다시 켜지거나, 새 버전을 배포하면 **비워진다.**

- 캐시가 비면 같은 조회를 다시 외부로 보낸다(결과는 같다).
- **KIPRIS 월 호출 수 집계(`quota_status`)가 0으로 돌아갈 수 있다.** 인스턴스가 여러 대면 대마다 따로 센다.
  그러면 서버의 `KIPRIS_MONTHLY_LIMIT` 멈춤 장치가 늦게 걸린다. 실제 월 한도는 KIPRIS가 끊으므로(오류 `QUOTA_EXCEEDED`·인증 오류로 보임) 키가 망가지지는 않는다.
- 대응: `--max-instances 1`로 한 대만 쓰고, 여유를 두려면 `KIPRIS_MONTHLY_LIMIT`를 실제보다 낮게(예: 800) 잡는다.
  정확한 월 집계가 꼭 필요하면 영구 저장소(Cloud Storage 볼륨 등)를 붙이는 별도 작업이 필요하다.
- `/tmp`도 메모리를 쓴다. 캐시가 아주 커지면 메모리(`--memory`)를 늘린다.

### 6-2. 사용자 추가·빼기

```bash
gcloud run services update "$SERVICE" --region "$REGION" \
  --update-env-vars "PATENT_API_ALLOWED_EMAILS=a@gmail.com;b@gmail.com"
```

새 버전이 뜨면 바로 적용된다. 목록에서 빠진 사람은 이미 받은 토큰도 다음 요청부터 거부된다.
①에서 퇴사자는 회사 워크스페이스 계정이 정지되면 구글 로그인 자체가 안 되고, 받은 토큰은 최대 30일(갱신 토큰 수명) 안에 만료된다.
즉시 끊으려면 아래 6-3.

### 6-3. 전원 강제 로그아웃·서명 키 교체

```bash
openssl rand -base64 48 | tr -d '\n' | gcloud secrets versions add patent-api-auth-secret --data-file=-
gcloud run services update "$SERVICE" --region "$REGION" --update-env-vars "SECRETS_ROTATED_AT=$(date +%s)"
```

모든 앱 등록·토큰이 무효가 되어 사용자는 다시 연결(로그인)해야 한다. ChatGPT·개인 Gemini는 커넥터를 다시 연결하고,
Gemini Enterprise는 직원이 다시 로그인한다.

### 6-4. 리디렉션 허용 호스트 바꾸기

기본값: `chatgpt.com;chat.openai.com;gemini.google.com;vertexaisearch.cloud.google.com;claude.ai;localhost;127.0.0.1`.
`PATENT_API_OAUTH_REDIRECT_HOSTS`를 넣으면 **목록 전체를 바꾼다**(기본값에 하나를 더하려면 기본값을 함께 적는다).

```bash
gcloud run services update "$SERVICE" --region "$REGION" \
  --update-env-vars "PATENT_API_OAUTH_REDIRECT_HOSTS=chatgpt.com;chat.openai.com;gemini.google.com;vertexaisearch.cloud.google.com;claude.ai;localhost;127.0.0.1;<추가호스트>"
```

호스트는 정확히 일치해야 하고, 내 컴퓨터(`localhost`, `127.0.0.1`)가 아니면 `https`만 받는다.

### 6-5. API 키 교체

```bash
read -rs v; printf '%s' "$v" | gcloud secrets versions add kipris-service-key --data-file=-; unset v
gcloud run services update "$SERVICE" --region "$REGION" --update-env-vars "SECRETS_ROTATED_AT=$(date +%s)"
```

`:latest`로 연결한 비밀은 새 버전(리비전)이 시작할 때 읽히므로, 값을 바꾼 뒤 위처럼 아무 환경변수나 바꿔 새 버전을 띄운다.

### 6-6. 로그와 비밀값

- 서버는 키·토큰·서명 키를 로그와 응답에 출력하지 않는다(오류 메시지도 키를 가린다). 접근 로그에서도 주소의 `?` 뒤를 지운다.
- 다만 **Cloud Run이 따로 남기는 요청 로그**에는 구글 로그인 복귀 주소(`/oauth/google/callback?code=...`)의 쿼리가 남을 수 있다.
  이 코드는 1회용·수 분짜리이고 구글 클라이언트 보안 비밀 없이는 쓸 수 없다. 로그 열람 권한은 관리자로 제한한다.
- 로그인 허용·거부는 **도메인만** 로그에 남긴다(이메일 주소 전체는 남기지 않는다).

### 6-7. 비용

요청이 없으면 0대로 꺼져 요금이 거의 없다(대신 첫 요청에 몇 초 걸린다). 항상 빠르게 하려면 `--min-instances 1`(상시 요금 발생).
Secret Manager·Cloud Build도 이 정도면 소액이다. 정확한 요금은 구글 클라우드 가격표를 본다.

## 8. 내 컴퓨터에서 먼저 시험하기

배포 전에 맥에서 HTTP 모드를 띄워 볼 수 있다. 4-3의 OAuth 클라이언트에 리디렉션 URI
`http://127.0.0.1:8080/oauth/google/callback`을 하나 더 넣어 두면 실제 구글 로그인까지 시험할 수 있다.

```bash
export PATENT_API_TRANSPORT=http PORT=8080 PATENT_API_PUBLIC_URL=http://127.0.0.1:8080
export PATENT_API_ALLOWED_EMAILS=<내메일> GOOGLE_OAUTH_CLIENT_ID=<클라이언트 ID>
read -rs GOOGLE_OAUTH_CLIENT_SECRET && export GOOGLE_OAUTH_CLIENT_SECRET
export PATENT_API_AUTH_SECRET=$(openssl rand -base64 48)
uv run server.py
```

다른 터미널에서 `curl -i -X POST http://127.0.0.1:8080/mcp` → `401`이면 정상이다. 로그인까지 보려면
`npx @modelcontextprotocol/inspector`를 열어 Transport `Streamable HTTP`, URL `http://127.0.0.1:8080/mcp`로 연결한다.
KIPRIS·EPO 키는 로컬과 같이 `.env`에서 읽는다.

## 9. 문제 해결

| 증상 | 원인·조치 |
|---|---|
| 서버가 시작하지 않고 `허용 목록이 비어 있어` | `PATENT_API_ALLOWED_DOMAINS`나 `PATENT_API_ALLOWED_EMAILS`를 넣는다 |
| `HTTP 모드 설정이 빠졌거나 잘못되었습니다: ...` | 적힌 항목을 넣는다(비밀값은 Secret Manager 연결 확인) |
| 구글 화면에 `redirect_uri_mismatch` | 4-3의 리디렉션 URI가 `$URL/oauth/google/callback`과 정확히 같은지 |
| 로그인 후 앱에 `access_denied` / "허용된 계정이 아닙니다" | 허용 목록 확인. 도메인 허용은 워크스페이스 계정만 통과한다 |
| 등록 단계에서 `invalid_redirect_uri` | 6-4에 앱의 리디렉션 호스트 추가(서버 로그에 호스트가 찍힌다) |
| Gemini Enterprise에서 `invalid_request` (code_challenge) | 커넥터 설정에서 PKCE를 켠다 |
| 도구 결과가 `CONFIG_MISSING_KEY` | KIPRIS·EPO 비밀 연결(`--set-secrets`)과 서비스 계정 권한 확인 |
| 갑자기 모두 다시 로그인해야 함 | 서명 키(`patent-api-auth-secret`)가 바뀌었는지 확인 |
